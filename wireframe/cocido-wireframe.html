Así se pierde el control

Nadie lee una tarde por cada PR.

1

Volumen

Cada PR trae miles de líneas plausibles. Compilan, pasan los tests, parecen bien.

2

Revisión en diagonal

Revisas línea a línea… hasta que no. Apruebas lo que no has leído.

3

Erosión silenciosa

Un módulo escribe en la tabla de otro. Un evento se publica fuera de la transacción. Nadie lo vio.

4

Descontrol

Ya nadie, ni tú ni el agente, sabe qué hace el sistema ni por qué.

La respuesta

Revisa la forma, no las líneas.

Cuatro piezas, una por cada momento de un cambio: plan, framework, review y monitor.

Plan · antes de escribir

cocido map --plan

El agente propone un plan por pasos. Se comprueba contra el código y las reglas antes de escribir nada.

Framework · mientras se escribe

cocido: DDD opinionado, con baterías

Una sola forma de hacer cada cosa, y la lint la hace cumplir: un agente no cruza una frontera sin que falle el build.

Review · antes de mergear

cocido review

La rama, dibujada contra su plan: hecho, falta, distinto o no planificado. Revisas eso.

Monitor · en producción

cocido-monitor

Ve lo que de verdad ejecuta y cierra el ciclo: lo que detecta vuelve al agente como una corrección a planificar.

Plan→Framework→Review→Monitor↺Corrección → Plan

El modelo

Fronteras que aguantan.

Domain-Driven Design al estilo de Eric Evans y Vaughn Vernon, hecho código: contextos delimitados, agregados, casos de uso y eventos de dominio.

Contextos con su propia base de datos, y módulos dueños de una entidad. Dentro de cada módulo, siempre las mismas piezas:

Caso de usolo que se puede pedir
Entidadsabe qué cambió
Eventosale por outbox, nunca se pierde
Repositorioescribe solo lo que cambió
Workerreacciona a eventos de otros
Schedulerlo que pasa a su hora

Repositorios

Un repositorio guarda las entidades de un módulo, escribe solo lo que cambió y publica sus eventos en la misma transacción.

import { defineRepository } from '@renacuajo/core' export const cards = defineRepository(Card, { table: 'cards' })

Sobre el control del software que ya no escribimos a mano

A quien construya con agentes: escribir código ha dejado de ser el cuello de botella. Ahora lo es entenderlo. Este texto explica qué creemos que hace falta para no perder el control, y cocido es la consecuencia.

  1. Lo que no se puede revisar, no se controla. Aprobar sin leer es delegar sin saberlo.
  2. Se revisa la forma, no las líneas. Las líneas las escribe la máquina; la forma la decide una persona.
  3. El plan va antes que el código. Y el código se contrasta con el plan, no con la intuición del revisor.
  4. Las fronteras se escriben en el código, no en un wiki. Un agente no lee el wiki. La lint, sí la cumple.
  5. Producción habla el idioma del dominio. Si no sabes qué hace en producción, no sabes qué escribiste.
  6. … hasta XII

Lo que cocido no será: un generador de código, un framework para todo, una caja de magia que no puedas leer.

— Angel Romero
